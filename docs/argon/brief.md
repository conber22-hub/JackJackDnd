## The situation

Codex has filled `src/data/` with the whole SRD 5.2.1:
- 330 creatures in `src/data/srd-monsters.js` (family `'srd'`, ids like `srd-young-red-dragon`)

Your three tasks turn that text into data and pure logic. Claude then wires the buttons, cards and panels. **You write pure modules and data with tests; you don't touch the UI.**

Your files are the ones each task names. Don't edit `src/data/srd-*.js` (Codex's) or anything in `src/game/`, `src/net/`, `src/render/`, `src/ui/` or `index.html` (Claude's).

## Task 1 — damage defenses (`argon/defenses`)

A new pure module, **`src/engine/defenses.js`** (no DOM, no Three.js), and **`tests/defenses.test.js`**.

1. `parseDefenses(traits)`:
   - Input: a creature's `traits` array of HTML strings.
   - Output: `{ resist:[], immune:[], vuln:[], condImmune:[] }`, lower-case damage types and condition names.
   - The SRD's lines look like this:
     - `<b>Resistances.</b> Bludgeoning, Lightning, Piercing, Slashing`
     - `<b>Immunities.</b> Poison, Psychic; Charmed, Deafened, Exhaustion` (damage types before the `;`, conditions after it)
     - `<b>Vulnerabilities.</b> Fire`
   - Handle every variant that occurs in `srd-monsters.js`. Write a test that runs over all 330 creatures and fails on any word that isn't a known damage type or condition.
2. `applyDefenses(parts, defenses)`:
   - `parts` is `[{ d:'2d6+3', t:'piercing', n:9 }, …]`, each part already rolled (`n`).
   - Returns `{ total, lines:[{ t, n, was, why }] }`: immune → 0, resistant → half (round down), vulnerable → double.
   - Each part counts separately. That's the point: a bite that is 4 force + 16 piercing against a creature resistant to piercing deals 4 + 8.
   - The SRD attacks already carry `parts` (see any `attacks[].parts` in `srd-monsters.js`).
3. `conditionImmune(defenses, cond)` → boolean.
4. Tests:
   - the parsing sweep over all 330 creatures
   - the rounding rules
   - a mixed-type attack
   - an empty-defences creature (nothing changes)

**Done means:** `npm test` and `npm run build` pass. The PR says how many creatures have each kind of defence. Claude will use it in `applyDamage` and when a condition is applied.

## Task 2 — monster actions (`argon/monster-actions`)

A new data overlay, **`src/data/monster-play.js`**, generated by **`scripts/import-monster-actions.mjs`** (which reads `srd-monsters.js`), with **`tests/monster-actions.test.js`**.

`MONSTER_PLAY` maps a creature id to what the table needs to *run* its non-attack actions:

```js
export const MONSTER_PLAY = {
  'srd-young-black-dragon': {
    defenses:{ resist:[], immune:['acid'], vuln:[], condImmune:[] },        // from Task 1's parseDefenses
    actions:[
      { n:'Acid Breath', k:'save', sv:'dex', dc:14, d:'11d8', ty:'acid', half:true, area:['line', 30], recharge:5 },
    ],
    legendary:3,                                                              // uses per round, if it has Legendary Actions
    resistDaily:3,                                                            // Legendary Resistance uses, if any
  },
};
```

What the fields mean:
- The action shape is the **same as a spell** in `src/data/srd.js` (`k`, `sv`, `dc`, `d`, `ty`, `half`, `area`, `cond`), so the app's area templates (`src/engine/targeting.js`: `sphere`, `cube`, `cone`, `line`, `cylinder`, `aura`) can aim it.
- `area` sizes are in feet.
- A line's length goes in `area[1]`; mention its width in a `note` if it isn't 5 ft.
- `recharge:5` means "Recharge 5–6"; `recharge:6` means "Recharge 6".
- `cond` is the condition a failed save gives, only when the text says so plainly. Put anything else (being pushed, swallowed, a later save) in a `note` string.

The rules:
- **Only what the text says.** Every number you output (DC, dice, area size, recharge) must appear in that creature's trait text. Add a test that checks this for every action.
- **Skip what doesn't fit.** If an action can't be expressed in this shape (Change Shape, Spellcasting, a gaze with an ongoing effect), leave it out. The DM still reads it.
- **Sweep the whole bestiary.** Add a test that runs every `area` through `areaSquares()` from `src/engine/targeting.js`, as `tests/spells.test.js` does for spells, and checks each one draws squares.
- **Report the gaps.** The PR description lists the counts: how many creatures got actions, defenses, legendary and resistance counts, and which common action patterns you skipped and why.

Claude will merge `MONSTER_PLAY` into the bestiary and add the buttons:
- the breath weapon aimed like a spell
- recharge rolled at the start of the creature's turn
- Legendary Resistance as a "use it" prompt when a save fails

## Task 3 — inventory engine (`argon/inventory`)

A new pure module, **`src/engine/inventory.js`**, with **`tests/inventory.test.js`**. It gives a hero things to carry and makes simple magic items count.

1. **The shape.** It lives on the hero sheet:
   ```js
   h.inv   = [{ id, n, qty, equipped:false, attuned:false }]   // n: a name from the catalogues in src/data/srd-items.js
   h.coins = { cp, sp, ep, gp, pp }
   ```
2. **Old sheets.** `migrateSheet(h)` returns a copy with `inv` built from the old fields when `inv` is missing:
   - `h.armor` → equipped armour
   - `h.shield` → an equipped Shield
   - `h.weapons` → equipped weapons
   - It never changes its argument. Old saves must keep working.
3. **Finding items.** `itemInfo(name)` finds the catalogue entry:
   - from `SRD_WEAPONS`, `ARMOR_ITEMS`, `TOOLS`, `GEAR` or `MAGIC_ITEMS`
   - including magic variants by name: `"Longsword, +1"` from the `"Weapon, +1, +2, or +3"` family; read the `variants`, `appliesTo`, `ac`, `dmgBonus` and `saves` fields Codex added
   - Returns `null` for anything unknown. Items from the DM's private library arrive as plain `{ n, text }`, so treat an unknown item as "carried, no effect".
4. **The rules.** `canEquip(h, id)` → `{ ok, why }`:
   - one body armour
   - one shield
   - at most 3 attuned items
   - two-handed weapons need no shield
5. **The effects.** `itemEffects(h)` → `{ ac, attack:{ [weaponName]:n }, damage:{ [weaponName]:n }, saves:n, spellAttack:n, spellDc:n, notes:[] }`:
   - from equipped (and, where required, attuned) items
   - only the simple, numeric effects the data carries
   - anything else goes in `notes` as the item's name, for the sheet
6. **Weight and coins.** `load(h, strength)` → `{ weight, capacity:strength*15, over:bool }`, and `coinValueGp(coins)`.
7. **Tests:**
   - migration of an old sheet
   - +1 armour and +2 weapons adding up
   - the attunement limit
   - a shield with a two-handed weapon
   - unknown items
   - every weapon and armour in the catalogue resolving through `itemInfo`

Don't change `src/engine/hero.js`. Instead, describe in the PR the three lines `heroStats`/`heroAttacks` need to apply `itemEffects` (AC, attack and damage bonuses). Claude will make that change together with the inventory panel on the hero sheet.
